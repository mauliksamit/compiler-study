# compiler-study — PyTorch eager vs torch.compile (Inductor) vs JAX/XLA, and a Triton kernel

A measured **study using existing compilers**, not compiler development. Two
Colab/Kaggle-compatible notebooks:

1. **`notebooks/01_block_eager_compile_xla.ipynb`** — one fixed-shape
   transformer block (pre-norm LayerNorm, causal attention, GELU MLP) run as
   PyTorch eager, `torch.compile` (Inductor), and `jax.jit` (XLA). FP32 with
   TF32 disabled, fixed seeds, numerics against a float64 NumPy reference,
   compile time reported separately from steady-state time. It saves the
   code each compiler generated (Inductor's output code with its Triton
   kernels; XLA's optimized HLO) and summarizes, **from those dumps only**,
   which operations were fused and which stayed separate (library GEMMs).
2. **`notebooks/02_triton_fused_softmax.ipynb`** — a row softmax written in
   Triton (single-block and looped online-softmax variants), a correctness
   gate on awkward shapes and three dtypes against float64, then a benchmark
   against the same softmax composed from eager PyTorch ops and against the
   library kernel `torch.softmax`.

Nothing here claims anything about MLIR or LLVM beyond what the saved dumps
show.

## Status

**Both notebooks: NOT RUN.** They need a Linux NVIDIA GPU (Triton and JAX's
CUDA build do not run on native Windows, where the related projects were
measured). Run them yourself on Colab or Kaggle following
[`RUNBOOK.md`](RUNBOOK.md), then `python scripts/ingest_results.py <zip>`.

What has been checked without a Linux GPU:
- Notebook 1 runs end to end locally on Windows: the eager and float64
  reference paths execute, and the `torch.compile` and JAX cells record
  NOT RUN with the exact error instead of crashing (smoke test only; those
  local numbers are not results and are not committed).
- Notebook 2's cells compile; the looped kernel's **algorithm** (per-lane
  online softmax with -inf guards) is verified against a float64 softmax by a
  NumPy emulation in `tests/` — this checks the math, not the Triton kernel.

## Layout

- `scripts/build_notebooks.py` — the notebooks' cell sources (reviewable);
  regenerates `notebooks/*.ipynb`.
- `scripts/ingest_results.py` — imports a results zip and renders README
  tables, `results/facts.json`, `docs/FACTS.md`.
- `tests/` — CPU tests (algorithm emulation; notebooks in sync with the builder).
- `docs/WRITEUP.md` — the fusion findings and softmax explanation, written
  from the dumps after the notebooks run (NOT RUN until then).
